@AGENTS.md

## What this is

Lumora's website and client platform: a public marketing site + portfolio, an account-gated **quote wizard**, a **client portal** (project timeline, quotes, invoices, Stripe payments) and an **admin dashboard** (quotes, clients, projects/milestones/updates, invoices, hosting & maintenance, portfolio, pricing).

## Stack (versions matter, so check before using APIs from memory)

- **Next.js 16** App Router + React 19, TypeScript, Turbopack. Read `node_modules/next/dist/docs/` before using unfamiliar APIs. Key differences from older Next:
  - `middleware.ts` is now **`src/proxy.ts`** exporting `proxy()`.
  - `params`, `searchParams`, `cookies()`, `headers()` are **async**. Use the global `PageProps<"/route">`, `LayoutProps`, `RouteContext` type helpers (generated by `next typegen`).
  - `next lint` is gone. Use `npm run lint` (ESLint CLI).
- **Tailwind CSS v4** (CSS-first config in `src/app/globals.css`, no `tailwind.config`).
- **Prisma 7** with the `prisma-client` generator → `src/generated/prisma` (git-ignored, generated on `postinstall`/`build`). Config in `prisma.config.ts`; uses the `@prisma/adapter-pg` driver adapter. Import types from `@/generated/prisma/client`.
- **Zod 4** (`z.email()`, `{ error }` messages), **jose** (session JWT), **bcryptjs**, **Stripe**, **Nodemailer** (Gmail SMTP) / **Resend**, **@react-pdf/renderer**.
- Tests: **Vitest** (unit, `src/**/*.test.ts`) and **Playwright** (e2e, `e2e/`, runs in local Google Chrome).

## Rendering model

`cacheComponents` is **deliberately off** (see `next.config.ts`). Portal and admin routes read the session cookie and the DB on every request, so they render dynamically. Public pages are **pre-built and served from the CDN**: the ones that read the DB (home, `/portfolio`, case studies, `sitemap.xml`, `llms.txt`) use `export const revalidate = 3600` and are refreshed straight away by `revalidatePath` in `admin/_actions/portfolio.ts`. Never add `connection()`, `cookies()` or session reads to a public page or the public layout: that makes it render per request (slow, and in the function region rather than at the edge). Wrap their DB reads in `buildSafe` (`src/lib/build-safe.ts`) so a build without a database still succeeds. Portal and admin have `loading.tsx` (`<PageLoading>`) so navigation responds instantly. Don't enable Cache Components without migrating every session-reading route (see `node_modules/next/dist/docs/01-app/02-guides/authentication-with-cache-components.md`).

## Conventions

- **Authorization lives in the Data Access Layer** (`src/lib/dal.ts`). Every page, server action and route handler touching private data must call `requireAdmin()`, `requireClient()` or `requireVerifiedClient()`, or `getCurrentUser()` + an explicit check. `proxy.ts` and layouts are *not* security boundaries.
- **Per-tab sign-in**: every tab must log in itself. `<TabSessionGuard>` (`src/components/tab-session.tsx`) wraps the portal, admin and `/quote` layouts and sends tabs without a sessionStorage flag to `/login` (other tabs stay signed in). Auth-page form submits set the flag; server redirects that sign someone in outside a form append `#signed-in`. `/login` and `/signup` always show their form. This is UX on top of the cookie, not a security boundary.
- **Scope client queries by owner**: `findFirst({ where: { id, clientId: user.id } })`, never `findUnique({ where: { id } })` in portal code. Clients never see `DRAFT` invoices.
- **Server actions** return `ActionState` (`src/lib/action-state.ts`) and are used with `<ActionForm>` (`src/components/forms.tsx`), which renders `error`, `message` and per-field errors. Validate with Zod, use `formToObject` + `fromZodError`/`fieldError`. Bind ids with `action.bind(null, id)`.
- **Money is integer pence** everywhere (DB, maths, Stripe). Convert at the edges with `poundsToPence` / `formatGBP` (`src/lib/money.ts`).
- **Never trust client-side prices**: the quote estimate is recomputed on the server (`calculateEstimate` + `getPriceMap`).
- **Client journey (quote → project → payment → launch → hosting)**:
  1. The wizard submits a quote (`SUBMITTED`). The admin confirms a fixed price, hosting plan, message and project title/dates and sends it (`sendQuoteOffer` → `SENT`, client emailed).
  2. On `/portal/quotes/[id]` the client **accepts** (choosing full payment or a 50% deposit), **requests changes** (the wizard reopens at `/quote?changes=<id>` with their answers; `requestQuoteChanges` stores the old answers in `previousAnswers`, their note in `changeRequest`, status `CHANGES_REQUESTED`; the admin sees the diff via `answerChanges` and re-sends) or **declines** (reason kept; can be re-sent). A sent quote can be withdrawn until the client replies.
  3. Accepting (`acceptOffer` in `src/lib/quote-accept.ts`, one transaction guarded by a conditional update) creates the project as `AWAITING_PAYMENT` ("Waiting for payment") and a numbered `SENT` invoice for the build (never hosting). When any invoice of that project becomes `PAID` (Stripe webhook or admin "Mark as paid"), `startProjectIfPaid` (`src/lib/project-payment.ts`) moves it to `PLANNING` and posts an update.
  4. "Mark as launched" on the admin project page (`launchProject`) completes the project and, if the accepted quote has paid hosting, creates the `HostingPlan` from it (`hostingFromQuote`, `planKey` set, renewal date today) and emails the client.
  5. In Portal → Hosting the client picks monthly or yearly and pays the first payment by card (`startPlan` → Stripe Checkout subscription), which saves the card; it then renews automatically. A launch plan with no payment yet is detected by `awaitingFirstPayment` (`src/lib/hosting.ts`); prices come from `planStartPrices` (`src/lib/hosting-start.ts`): the quoted price for the quoted interval, the price list for the other.
  Admins no longer create projects from quotes directly. Pure helpers: `src/lib/quote-offer.ts`.
- **Hosting billing**: plans are invoiced each period ("Invoice next period") until the client switches to automatic card payments from Portal → Hosting (Stripe subscription, `src/lib/hosting-billing.ts`). If the current period is already paid, the first charge waits until `renewalDate`. Each subscription payment (`invoice.paid`) is recorded as a numbered PAID invoice (`Invoice.stripeInvoiceId`). Clients can cancel (ends at the end of the paid period, `HostingPlan.cancelAt`) and undo it; card-billed or cancelled plans can't be manually invoiced. Billing state for UI comes from `hostingBillingState` (`src/lib/hosting.ts`). The webhook handles `checkout.session.*`, `customer.subscription.*` and `invoice.paid` / `invoice.payment_failed`.
- **Invoices bill a quote**: `Invoice.quoteId` links what the client picked (package + hosting plan, shown on the invoice via `src/lib/invoice-details.ts`; load it with `withQuote` from `src/lib/invoice-quote.ts`, not by joining it into `invoiceViewInclude`). "Create & send to client" issues and emails in one step.
- **Invoice numbers** (`LUM-YYYY-NNNN`) are allocated only when an invoice is **sent** (`sendInvoice` → `nextInvoiceNumber` in a transaction), so deleted drafts never leave gaps. Invoices can be deleted from the admin (`deleteInvoice`), paid ones too; this leaves a gap in the numbering.
- **Theme (light lavender)**: all UI colours are CSS variables in `src/app/globals.css` exposed as Tailwind tokens (`bg-canvas`, `bg-surface`, `bg-surface-2`, `text-ink`, `text-ink-muted`, `border-line`, `bg-brand`, `text-on-brand`, `text-brand-light`, `bg-brand-tint`, `bg-brand-soft`). **Never hard-code hex or rgba colours in components**; for coloured shadows use `color-mix(in_oklab,var(--brand)_40%,transparent)` or `var(--glow)`. Palette: `#F8F7FF` (canvas), `#17152B` (`ink` text), `#8B5CF6` purple (`brand`), `#DDD6FE` soft lavender (`brand-tint`). `brand` is for **fills** and takes `text-on-brand` (white); for purple **text**/links use `text-brand-light` (deeper purple, AA on white); `brand-tint` is the soft lavender used in gradients. A few deliberate dark accents (home CTA band, quote estimate card) use `brand` → `brand-deep` → `ink` gradients with white text. Backgrounds are smooth: `<FlowBackground>` (mesh + drifting blobs + wave ribbons) and the `bg-mesh` utility; no grid/grain patterns. Headings use `font-display` (Cormorant Garamond). Other utilities: `glass`, `glow`, `ring-gradient`, `text-gradient`, `spotlight`, `shine`. Emails and the invoice PDF stay light with their own brand hex copies.
- **Motion**: use `<Reveal>` (scroll fade-up, optional `delay`; it slides with `top`, not `transform`, because text moved with `transform` looks blurry until the motion ends) and `<Spotlight>` / `<Card interactive>` (cursor glow + hover lift) from `src/components/motion.tsx` / `ui.tsx`. Keep animations CSS-only; globals.css disables them under `prefers-reduced-motion`. **Content must never wait for JavaScript to become visible**: `<Reveal>` is server-rendered as a CSS-only entrance (`data-reveal="load"`) and only holds back elements that are still below the screen after hydration. **Keep phones cheap to draw**: no large `blur-[…]` glows (use a `radial-gradient` instead) and no animated blurred layers below `md` (`<FlowBackground>` shows only the mesh and still ribbons on phones). Client components (Spotlight, Reveal) cannot receive components/functions as props from server components (e.g. don't pass `as={Link}`; wrap instead).
- **Logo**: the LUMORA wordmark is an inline SVG (`Wordmark`/`Logo` in `src/components/logo.tsx`); a static copy is `public/logo.svg`. Every tab/app icon is a white Cormorant "L" on a purple gradient, generated by `npm run icons` (`scripts/generate-icons.tsx`, font in `scripts/icons/`): `src/app/favicon.ico` (16/32/48, for browsers that request `/favicon.ico`, which includes most mobile ones), `src/app/icon1.png` (32) + `icon2.png` (192), `src/app/apple-icon.png` (180, solid square, because iOS turns transparency black) and `public/icon-192.png` / `icon-512.png` (manifest, also maskable). Edit the script and re-run it rather than editing the PNGs. The original wordmark tile (`public/lumora_profile_pic_*.png`) is only used in the share image (`src/app/opengraph-image.tsx`).
- **Portfolio case studies**: content lives in `prisma/portfolio-data.ts` (re-running the seed refreshes it) and is editable in Admin → Portfolio. Website visuals are built-in mockups in `src/components/mockups/` (one file per client: `Desktop`, `Mobile`, `Detail`), registered in `mockups/index.ts` and selected via `PortfolioItem.mockup`. They are written with normal Tailwind classes at design size (1280px desktop / 390px phone) and scale via the `mock-desktop` / `mock-phone` utilities in globals.css. Client brand colours inside mockup files are a deliberate exception to the no-hex rule. Product/food imagery uses free Unsplash photos in `src/components/mockups/photos/` (credited in its `CREDITS.md`), shown with the `Photo` helper in `frames.tsx`; only use Unsplash License photos, never Unsplash+. **Never invent results or testimonials**: the `stats` and `testimonial*` fields must hold real client figures/quotes and stay hidden when empty. Don't show real-looking domains in mockup frames.
- **SEO / GEO**: indexable public pages use `pageMetadata()` from `src/lib/seo.ts` (canonical + full Open Graph/Twitter tags, since Next merges `openGraph` shallowly). Organisation/WebSite JSON-LD is in the public layout; render other structured data with `<JsonLd>` (`src/components/json-ld.tsx`). `/llms.txt` (`src/app/llms.txt/route.ts`) summarises the site for AI assistants from `content.ts` + published portfolio items. Auth, quote, portal and admin pages are `noindex` and disallowed in `robots.ts`. The share image is `src/app/opengraph-image.tsx`.
- **Admin deletes are full deletes** (`src/lib/delete-records.ts`, buttons use `<ConfirmSubmit>` from `src/components/confirm-button.tsx`): everything linked goes too, **paid invoices included** (not refunded; the payment stays in Stripe), and it all disappears from the portal. `deleteInvoice` deletes any invoice. `deleteHostingPlan` → `deleteHostingPlans` cancels the Stripe subscription first (nothing is deleted if that fails), then deletes the plan and all its invoices. `deleteQuote` and `deleteProject` → `deleteQuoteAndProject` delete the quote, its project (milestones, updates), every invoice of either and the project's hosting plans. Open Checkout pages for deleted invoices are expired (`expireCheckoutSessions`).
- **Client reviews** live in the `reviews` array in `src/lib/content.ts` and render above the FAQs (`src/components/faq.tsx`); real quotes only, hidden while empty.
- **Client portal overview** shows one "next step" card chosen by `portalNextStep` (`src/lib/portal.ts`). Keep the portal to that plus the project list; don't add more panels.
- Pure, testable logic goes in `src/lib/*.ts` without `server-only` (pricing, invoice, hosting, progress, money). Server-only modules import `"server-only"`.
- Keep the quote wizard catalogue (`src/lib/pricing.ts`) and the `PricingItem` table in sync: new keys need a `DEFAULT_PRICES` entry and get picked up by the seed + admin pricing page.

## Environment

See `.env.example`. Email goes via SMTP (`SMTP_*`, e.g. Gmail App Password) if set, else Resend (`RESEND_API_KEY`); with neither, emails are NOT sent and are printed to the dev server log (the check-email page shows a dev-only notice). `emailProvider()` in `src/lib/email.ts` reports which is active (pure logic in `src/lib/email-provider.ts`); `EMAIL_TRANSPORT=console` forces the console fallback outside production (Playwright sets it, and reads links from `.e2e-dev.log`). Never put real credentials in `.env.example`. Business contact details (email, Instagram) live in `src/lib/site.ts`; FAQs in `src/lib/content.ts`. Without Stripe keys, "Pay now" shows a friendly error. With test keys (`sk_test_…` + `STRIPE_WEBHOOK_SECRET`), the e2e suite opens a real test-mode Checkout and posts a signed `checkout.session.completed` webhook; it never runs payments against live keys. Paid invoices email the client (`invoicePaid`) and `ADMIN_NOTIFY_EMAIL` (`adminInvoicePaid`), once per invoice. `DISABLE_RATE_LIMIT=true` relaxes the in-memory rate limiter in dev only (used by Playwright).

## Gotchas

- Playwright starts its own dev server on **port 3100** with `NEXT_DIST_DIR=.next-e2e` and `EMAIL_TRANSPORT=console`, so it runs beside your `npm run dev` and never sends real email. Next adds `.next-e2e` entries to `tsconfig.json`; keep them.
- Next.js adds a hidden `role="alert"` route announcer. In Playwright, target `p[role=alert]` or headings rather than `getByRole("alert")`.
- `src/lib/rate-limit.ts` is in-memory (per instance). Replace with a shared store before relying on it in serverless production.
- **Deploys** run `prisma db push` then `prisma/bootstrap.ts` (see `build` in package.json): it creates/updates the admin from `ADMIN_EMAIL`/`ADMIN_PASSWORD`, adds missing prices, and loads portfolio case studies only into an empty table. No demo data. The full `npm run db:seed` is for local/dev databases. Admin logic is shared in `prisma/admin.ts`.
- `APP_URL` without a scheme is treated as `https://` (`src/lib/site.ts`).
- `prisma/seed.ts` builds its own PrismaClient (it can't import `src/lib/db.ts`, which is `server-only`).
