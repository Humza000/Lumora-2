@AGENTS.md

## What this is

Lumora's website and client platform: a public marketing site + portfolio, an account-gated **quote wizard**, a **client portal** (project timeline, quotes, invoices, Stripe payments) and an **admin dashboard** (quotes, clients, projects/milestones/updates, invoices, hosting & maintenance, portfolio, pricing).

## Stack (versions matter, so check before using APIs from memory)

- **Next.js 16** App Router + React 19, TypeScript, Turbopack. Read `node_modules/next/dist/docs/` before using unfamiliar APIs. Key differences from older Next:
  - `middleware.ts` is now **`src/proxy.ts`** exporting `proxy()`.
  - `params`, `searchParams`, `cookies()`, `headers()` are **async**. Use the global `PageProps<"/route">`, `LayoutProps`, `RouteContext` type helpers (generated by `next typegen`).
  - `next lint` is gone. Use `npm run lint` (ESLint CLI).
- **Tailwind CSS v4** (CSS-first config in `src/app/globals.css`, no `tailwind.config`).
- **Prisma 7** with the `prisma-client` generator → `src/generated/prisma` (git-ignored, generated on `postinstall`/`build`). Config in `prisma.config.ts`; uses the `@prisma/adapter-pg` driver adapter. Import types from `@/generated/prisma/client`.
- **Zod 4** (`z.email()`, `{ error }` messages), **jose** (session JWT), **bcryptjs**, **Stripe**, **Nodemailer** (Gmail SMTP) / **Resend**, **@react-pdf/renderer**.
- Tests: **Vitest** (unit, `src/**/*.test.ts`) and **Playwright** (e2e, `e2e/`, runs in local Google Chrome).

## Rendering model

`cacheComponents` is **deliberately off** (see `next.config.ts`). Portal and admin routes read the session cookie and the DB on every request, so they render dynamically. Public pages that read the DB call `await connection()` so builds don't need a database. Don't enable Cache Components without migrating every session-reading route (see `node_modules/next/dist/docs/01-app/02-guides/authentication-with-cache-components.md`).

## Conventions

- **Authorization lives in the Data Access Layer** (`src/lib/dal.ts`). Every page, server action and route handler touching private data must call `requireAdmin()`, `requireClient()` or `requireVerifiedClient()`, or `getCurrentUser()` + an explicit check. `proxy.ts` and layouts are *not* security boundaries.
- **Per-tab sign-in**: every tab must log in itself. `<TabSessionGuard>` (`src/components/tab-session.tsx`) wraps the portal, admin and `/quote` layouts and sends tabs without a sessionStorage flag to `/login` (other tabs stay signed in). Auth-page form submits set the flag; server redirects that sign someone in outside a form append `#signed-in`. `/login` and `/signup` always show their form. This is UX on top of the cookie, not a security boundary.
- **Scope client queries by owner**: `findFirst({ where: { id, clientId: user.id } })`, never `findUnique({ where: { id } })` in portal code. Clients never see `DRAFT` invoices.
- **Server actions** return `ActionState` (`src/lib/action-state.ts`) and are used with `<ActionForm>` (`src/components/forms.tsx`), which renders `error`, `message` and per-field errors. Validate with Zod, use `formToObject` + `fromZodError`/`fieldError`. Bind ids with `action.bind(null, id)`.
- **Money is integer pence** everywhere (DB, maths, Stripe). Convert at the edges with `poundsToPence` / `formatGBP` (`src/lib/money.ts`).
- **Never trust client-side prices**: the quote estimate is recomputed on the server (`calculateEstimate` + `getPriceMap`).
- **Invoice numbers** (`LUM-YYYY-NNNN`) are allocated only when an invoice is **sent** (`sendInvoice` → `nextInvoiceNumber` in a transaction), so deleted drafts never leave gaps. Issued invoices are voided, never deleted.
- **Theme (light lavender)**: all UI colours are CSS variables in `src/app/globals.css` exposed as Tailwind tokens (`bg-canvas`, `bg-surface`, `bg-surface-2`, `text-ink`, `text-ink-muted`, `border-line`, `bg-brand`, `text-on-brand`, `text-brand-light`, `bg-brand-tint`, `bg-brand-soft`). **Never hard-code hex or rgba colours in components**; for coloured shadows use `color-mix(in_oklab,var(--brand)_40%,transparent)` or `var(--glow)`. Palette: `#F8F7FF` (canvas), `#17152B` (`ink` text), `#8B5CF6` purple (`brand`), `#DDD6FE` soft lavender (`brand-tint`). `brand` is for **fills** and takes `text-on-brand` (white); for purple **text**/links use `text-brand-light` (deeper purple, AA on white); `brand-tint` is the soft lavender used in gradients. A few deliberate dark accents (home CTA band, quote estimate card) use `brand` → `brand-deep` → `ink` gradients with white text. Backgrounds are smooth: `<FlowBackground>` (mesh + drifting blobs + wave ribbons) and the `bg-mesh` utility; no grid/grain patterns. Headings use `font-display` (Cormorant Garamond). Other utilities: `glass`, `glow`, `ring-gradient`, `text-gradient`, `spotlight`, `shine`. Emails and the invoice PDF stay light with their own brand hex copies.
- **Motion**: use `<Reveal>` (scroll fade-up, optional `delay`) and `<Spotlight>` / `<Card interactive>` (cursor glow + hover lift) from `src/components/motion.tsx` / `ui.tsx`. Keep animations CSS-only; globals.css disables them under `prefers-reduced-motion`. Client components (Spotlight, Reveal) cannot receive components/functions as props from server components (e.g. don't pass `as={Link}`; wrap instead).
- **Logo**: the LUMORA wordmark is an inline SVG (`Wordmark`/`Logo` in `src/components/logo.tsx`); a static copy is `public/logo.svg`. The original square brand tile (`public/lumora_profile_pic_*.png`) is used as the favicon/app icon via `src/app/icon.png` and `src/app/apple-icon.png`.
- **Portfolio case studies**: content lives in `prisma/portfolio-data.ts` (re-running the seed refreshes it) and is editable in Admin → Portfolio. Website visuals are built-in mockups in `src/components/mockups/` (one file per client: `Desktop`, `Mobile`, `Detail`), registered in `mockups/index.ts` and selected via `PortfolioItem.mockup`. They are written with normal Tailwind classes at design size (1280px desktop / 390px phone) and scale via the `mock-desktop` / `mock-phone` utilities in globals.css. Client brand colours inside mockup files are a deliberate exception to the no-hex rule. **Never invent results or testimonials**: the `stats` and `testimonial*` fields must hold real client figures/quotes and stay hidden when empty. Don't show real-looking domains in mockup frames.
- **Client reviews** live in the `reviews` array in `src/lib/content.ts` and render above the FAQs (`src/components/faq.tsx`); real quotes only, hidden while empty.
- **Client portal overview** shows one "next step" card chosen by `portalNextStep` (`src/lib/portal.ts`). Keep the portal to that plus the project list; don't add more panels.
- Pure, testable logic goes in `src/lib/*.ts` without `server-only` (pricing, invoice, hosting, progress, money). Server-only modules import `"server-only"`.
- Keep the quote wizard catalogue (`src/lib/pricing.ts`) and the `PricingItem` table in sync: new keys need a `DEFAULT_PRICES` entry and get picked up by the seed + admin pricing page.

## Environment

See `.env.example`. Email goes via SMTP (`SMTP_*`, e.g. Gmail App Password) if set, else Resend (`RESEND_API_KEY`); with neither, emails are NOT sent and are printed to the dev server log (the check-email page shows a dev-only notice). `emailProvider()` in `src/lib/email.ts` reports which is active (pure logic in `src/lib/email-provider.ts`); `EMAIL_TRANSPORT=console` forces the console fallback outside production (Playwright sets it, and reads links from `.e2e-dev.log`). Never put real credentials in `.env.example`. Business contact details (email, Instagram) live in `src/lib/site.ts`; FAQs in `src/lib/content.ts`. Without Stripe keys, "Pay now" shows a friendly error. `DISABLE_RATE_LIMIT=true` relaxes the in-memory rate limiter in dev only (used by Playwright).

## Gotchas

- Playwright starts its own dev server on **port 3100** with `NEXT_DIST_DIR=.next-e2e` and `EMAIL_TRANSPORT=console`, so it runs beside your `npm run dev` and never sends real email. Next adds `.next-e2e` entries to `tsconfig.json`; keep them.
- Next.js adds a hidden `role="alert"` route announcer. In Playwright, target `p[role=alert]` or headings rather than `getByRole("alert")`.
- `src/lib/rate-limit.ts` is in-memory (per instance). Replace with a shared store before relying on it in serverless production.
- `prisma/seed.ts` builds its own PrismaClient (it can't import `src/lib/db.ts`, which is `server-only`).
