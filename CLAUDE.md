@AGENTS.md

## What this is

Lumora's website and client platform: a public marketing site + portfolio, an account-gated **quote wizard**, a **client portal** (project timeline, quotes, invoices, Stripe payments) and an **admin dashboard** (quotes, clients, projects/milestones/updates, invoices, hosting & maintenance, portfolio, pricing).

## Stack (versions matter, so check before using APIs from memory)

- **Next.js 16** App Router + React 19, TypeScript, Turbopack. Read `node_modules/next/dist/docs/` before using unfamiliar APIs. Key differences from older Next:
  - `middleware.ts` is now **`src/proxy.ts`** exporting `proxy()`.
  - `params`, `searchParams`, `cookies()`, `headers()` are **async**. Use the global `PageProps<"/route">`, `LayoutProps`, `RouteContext` type helpers (generated by `next typegen`).
  - `next lint` is gone. Use `npm run lint` (ESLint CLI).
- **Tailwind CSS v4** (CSS-first config in `src/app/globals.css`, no `tailwind.config`).
- **Prisma 7** with the `prisma-client` generator → `src/generated/prisma` (git-ignored, generated on `postinstall`/`build`). Config in `prisma.config.ts`; uses the `@prisma/adapter-pg` driver adapter. Import types from `@/generated/prisma/client`.
- **Zod 4** (`z.email()`, `{ error }` messages), **jose** (session JWT), **bcryptjs**, **Stripe**, **Resend**, **@react-pdf/renderer**.
- Tests: **Vitest** (unit, `src/**/*.test.ts`) and **Playwright** (e2e, `e2e/`, runs in local Google Chrome).

## Rendering model

`cacheComponents` is **deliberately off** (see `next.config.ts`). Portal and admin routes read the session cookie and the DB on every request, so they render dynamically. Public pages that read the DB call `await connection()` so builds don't need a database. Don't enable Cache Components without migrating every session-reading route (see `node_modules/next/dist/docs/01-app/02-guides/authentication-with-cache-components.md`).


## Conventions

- **Authorization lives in the Data Access Layer** (`src/lib/dal.ts`). Every page, server action and route handler touching private data must call `requireAdmin()`, `requireClient()` or `requireVerifiedClient()`, or `getCurrentUser()` + an explicit check. `proxy.ts` and layouts are *not* security boundaries.
- **Scope client queries by owner**: `findFirst({ where: { id, clientId: user.id } })`, never `findUnique({ where: { id } })` in portal code. Clients never see `DRAFT` invoices.
- **Server actions** return `ActionState` (`src/lib/action-state.ts`) and are used with `<ActionForm>` (`src/components/forms.tsx`), which renders `error`, `message` and per-field errors. Validate with Zod, use `formToObject` + `fromZodError`/`fieldError`. Bind ids with `action.bind(null, id)`.
- **Money is integer pence** everywhere (DB, maths, Stripe). Convert at the edges with `poundsToPence` / `formatGBP` (`src/lib/money.ts`).
- **Never trust client-side prices**: the quote estimate is recomputed on the server (`calculateEstimate` + `getPriceMap`).
- **Invoice numbers** (`LUM-YYYY-NNNN`) are allocated only when an invoice is **sent** (`sendInvoice` → `nextInvoiceNumber` in a transaction), so deleted drafts never leave gaps. Issued invoices are voided, never deleted.
- **Theme**: brand colours are CSS variables in `src/app/globals.css` exposed as Tailwind tokens (`bg-brand`, `text-ink`, `bg-surface`, `border-line`, …). **Never hard-code hex colours in components.** The PDF (`src/lib/invoice-pdf.tsx`) and emails (`src/lib/email.ts`) can't read CSS vars and have their own copies, so keep them in sync.
- **Logo**: `public/logo.svg`, referenced via `site.logo` in `src/lib/site.ts`.
- Pure, testable logic goes in `src/lib/*.ts` without `server-only` (pricing, invoice, hosting, progress, money). Server-only modules import `"server-only"`.
- Keep the quote wizard catalogue (`src/lib/pricing.ts`) and the `PricingItem` table in sync: new keys need a `DEFAULT_PRICES` entry and get picked up by the seed + admin pricing page.

## Environment

See `.env.example`. Without `RESEND_API_KEY`, emails (including verification links) print to the dev server console. Without Stripe keys, "Pay now" shows a friendly error. `DISABLE_RATE_LIMIT=true` relaxes the in-memory rate limiter in dev only (used by Playwright).

## Gotchas

- Next.js adds a hidden `role="alert"` route announcer. In Playwright, target `p[role=alert]` or headings rather than `getByRole("alert")`.
- `src/lib/rate-limit.ts` is in-memory (per instance). Replace with a shared store before relying on it in serverless production.
- `prisma/seed.ts` builds its own PrismaClient (it can't import `src/lib/db.ts`, which is `server-only`).
